# ТЗ: Telegram-бот платных таро-гаданий («TarotBot»)

## 1. Идея и позиционирование

Telegram-бот, который делает персонализированные таро-расклады за плату.
Отличие от конкурентов — не «нажми кнопку, получи случайный текст», а:

- **персонализация**: бот знает имя, дату рождения и историю прошлых раскладов клиента,
  умеет отвечать на уточняющие вопросы по уже сделанному раскладу;
- **живой ритуал**: пользователь формулирует вопрос своими словами, бот «тянет» карты
  по-настоящему (случайность + перевёрнутые карты), показывает изображения карт;
- **воронка**: бесплатная «карта дня» каждый день → удержание → конверсия в платные расклады;
- **честность**: вся история гаданий сохраняется и доступна пользователю.

## 2. Ключевые решения (зафиксировано)

| Вопрос | Решение | Почему |
|---|---|---|
| Генерация текста | Облачный LLM по API (за прослойкой-интерфейсом) | Оплата за факт использования, копеечная себестоимость расклада, не нужен мощный сервер. Локальная Gemma — отложена до v3 (см. §9): требует 8–16+ ГБ RAM/GPU и даёт худший русский текст |
| Приём оплаты | **Telegram Stars (XTR)** | Требование правил Telegram для цифровых услуг в ботах; работает во всех странах, без договоров с платёжными провайдерами |
| Язык/фреймворк | Python 3.12 + aiogram 3.x | Зрелая экосистема, встроенная поддержка платежей и FSM-диалогов |
| БД | SQLite (MVP) → PostgreSQL (при росте) | Ноль администрирования на старте; схема пишется совместимой |
| Деплой | Docker на дешёвом VPS (1 vCPU / 1 ГБ хватит), long polling | Webhook и масштабирование — позже, когда появится нагрузка |

## 3. Функциональность MVP (этап 1)

### 3.1 Онбординг
- `/start` — приветствие, короткое знакомство: бот спрашивает **имя** и **дату рождения**
  (можно пропустить), сохраняет в профиль.
- Сразу предлагает бесплатную «карту дня» — мгновенная ценность до любой оплаты.

### 3.2 Карта дня (бесплатно, 1 раз в сутки)
- Случайная карта из полной колоды (78 карт, включая перевёрнутые).
- Изображение карты + короткая LLM-интерпретация с учётом имени пользователя.
- Если карта дня уже получена — показать её же и время до следующей.
- В конце сообщения — мягкий апселл: «Хочешь разобрать конкретный вопрос? → Расклады».

### 3.3 Платные расклады
Каталог (цены в Stars — подобрать после запуска, ориентиры ниже):

| Расклад | Карт | Ориентир цены |
|---|---|---|
| «Одна карта» — быстрый ответ на вопрос | 1 | 25 ⭐ |
| «Прошлое–Настоящее–Будущее» | 3 | 50 ⭐ |
| «Отношения» (я / партнёр / что между нами / совет) | 4 | 75 ⭐ |
| «Кельтский крест» — глубокий разбор | 10 | 150 ⭐ |

Флоу платного расклада:
1. Пользователь выбирает расклад из меню (inline-кнопки).
2. Бот просит сформулировать вопрос свободным текстом (FSM-состояние).
3. Бот выставляет счёт (`sendInvoice`, валюта XTR).
4. После `successful_payment` — «ритуал»: бот по одной показывает вытянутые карты
   (изображение + название + позиция в раскладе), затем присылает цельную интерпретацию.
5. Интерпретацию генерирует LLM по промпту, куда подставляются: вопрос, карты и их позиции
   (прямые/перевёрнутые), имя, дата рождения, краткие итоги 2–3 последних раскладов.

### 3.4 Уточняющие вопросы (ключевой дифференциатор)
- После каждого платного расклада — 2 бесплатных уточняющих вопроса по нему
  (LLM отвечает в контексте этого расклада).
- Дальнейшие уточнения — 10 ⭐ за вопрос.

### 3.5 История
- `/history` — список прошлых раскладов, по нажатию — полный текст.

### 3.6 Обязательное по правилам платежей
- Обработка `pre_checkout_query` (ответ в течение 10 секунд).
- `/paysupport` — контакты поддержки и политика возвратов (обязательна для Stars).
- Команда возврата в админке (`refundStarPayment`).
- Дисклеймер «развлекательный сервис, не является профессиональной консультацией» — в
  `/start` и в описании бота.

### 3.7 Админка (минимум, прямо в боте, по списку admin id)
- `/stats` — пользователи (всего/новых за день), раскладов за день, выручка в Stars.
- `/refund <charge_id>` — возврат.
- `/broadcast` — рассылка (с подтверждением).

## 4. Данные

```
users:     id, tg_id, name, birth_date, created_at, daily_card_date, referrer_id
readings:  id, user_id, type, question, cards_json, interpretation, created_at,
           price_stars, payment_charge_id, clarifications_left
payments:  id, user_id, reading_id, stars, charge_id, status(paid/refunded), created_at
```

Колода — статический JSON: 78 карт, для каждой: название (рус/англ), аркан/масть,
краткие значения (прямое/перевёрнутое), путь к изображению. Изображения — из открытой
колоды Райдера–Уэйта (public domain), лежат в репозитории.

## 5. LLM-прослойка

- Единый интерфейс `Interpreter.interpret(spread, question, profile, history) -> str`
  и `Interpreter.clarify(reading, question) -> str`.
- Реализация MVP — облачный API; провайдер и модель задаются через env-переменные.
- Системный промпт: тёплый, образный тон таролога; обязательно вплетать конкретные
  вытянутые карты и их позиции; без медицинских/юридических/финансовых директивных советов;
  ответ 150–400 слов; обращение по имени.
- Таймаут + 1 ретрай; при полном отказе LLM — fallback-интерпретация из статических
  значений карт (пользователь не должен остаться без результата после оплаты).
- Логировать себестоимость (токены) каждого расклада — контролировать маржу.

## 6. Нефункциональные требования

- Все ключи (токен бота, ключ LLM) — только через env / `.env` (в `.gitignore`).
- Идемпотентность оплат: повторный `successful_payment` с тем же `charge_id` не создаёт
  второй расклад.
- Ошибки после оплаты не теряют деньги: расклад создаётся в БД **до** генерации текста,
  генерация ретраится/доделывается фоном.
- Логи всех платежей и ошибок; sentry/логи-файл — по вкусу.
- Бэкап SQLite-файла раз в сутки (cron + копия наружу).

## 7. Этап 2 (после проверки спроса)

- **Подписка** «Премиум» (Stars-subscription, помесячно): карта дня расширенная,
  скидка на расклады, безлимит уточнений.
- **Реферальная программа**: персональная ссылка, бонусные ⭐/бесплатный расклад за друга.
- Напоминание о карте дня (opt-in push утром) — главный инструмент удержания.
- Больше раскладов: «Да/Нет», «Финансы», «Неделя», «Год» (сезонное — на праздники).
- Натальная привязка: интерпретации учитывают знак зодиака из даты рождения.

## 8. Этап 3 (масштабирование)

- PostgreSQL + webhook + несколько воркеров.
- A/B-тесты цен, аналитика воронки (amplitude/self-hosted).
- Голосовые вопросы (speech-to-text), озвучка интерпретации.
- **Здесь** имеет смысл вернуться к идее локальной модели (Gemma и т.п.): когда объём
  раскладов таков, что аренда GPU-сервера дешевле API. Благодаря прослойке из §5 это
  замена одного класса, не переписывание бота.

## 9. Почему не Gemma сейчас (зафиксировать, чтобы не возвращаться)

1. Даже «маленькой» модели нужно 8–16+ ГБ RAM; на CPU-VPS генерация занимает десятки
   секунд на расклад — это убивает UX.
2. Качество длинного образного русского текста у малых локальных моделей ощутимо ниже —
   а текст и есть продукт.
3. Экономика: API-себестоимость одного расклада — единицы центов при цене расклада
   ~1–2 $. GPU-сервер окупается только при сотнях раскладов в день.

## 10. План работ MVP

| # | Работа | Оценка |
|---|---|---|
| 1 | Каркас: aiogram, конфиг, БД, миграции, Docker | 1 день |
| 2 | Колода: JSON 78 карт + изображения + механика тяги | 1 день |
| 3 | Онбординг + карта дня | 1 день |
| 4 | Каталог раскладов, FSM вопроса, оплата Stars, идемпотентность | 2 дня |
| 5 | LLM-прослойка, промпты, fallback | 1–2 дня |
| 6 | Уточняющие вопросы, история | 1 день |
| 7 | Админка, /paysupport, возвраты | 1 день |
| 8 | Тесты платёжного флоу, деплой, бэкапы | 1 день |

**Итого MVP: ~9–10 рабочих дней.**

## 11. Метрики успеха (смотреть с первого дня)

- DAU и возврат на карту дня (retention D1/D7);
- конверсия «карта дня → первый платный расклад»;
- средний чек и выручка/день в Stars;
- доля повторных покупок (главный сигнал качества интерпретаций);
- себестоимость LLM на один расклад (маржа).
